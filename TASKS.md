## Setup Prerequisites

Before running TeamNode, ensure these are configured:

### API Keys (in ~/.bashrc or ~/.config/teamnode/config.json)

```bash
export ANTHROPIC_API_KEY="sk-ant-..."         # Required — Claude for all agents
export BRAVE_SEARCH_API_KEY="BSA..."          # Web search — Brave (own index, $5 free credits/month)
export BING_SEARCH_API_KEY="..."              # Web search — Bing (Azure, 1,000 free/month)
```

Either Brave or Bing works standalone. Both together enables cross-validation
(results appearing in both engines are marked high confidence).

### Fabric Binary

The Ecphory fabric CLI must be built:
```bash
cd ~/projects/intent-node
cargo build --release
```

Binary at: `~/projects/intent-node/target/release/intent`
Data directory: `~/.ecphory/projects/{project}/fabric.json`

The bridge passes `ECPHORY_DATA_DIR=~/.ecphory/` to the subprocess so all
tools share the same fabric regardless of working directory.

## Current Architecture

```
You type a goal
  → Python router (keyword matching, no LLM tokens)
    → Planner/Researcher runs first (fabric search + web search)
      → Primary domain agent runs second (uses Planner context)
        → All outputs stored in Ecphory fabric
          → Decisions logged to markdown

Fabric data: ~/.ecphory/projects/{project}/fabric.json
Web search: Brave + Bing cross-validation
LLM: Anthropic Claude (Sonnet for domain agents, Opus for Planner)
Local fallback: Ollama (--ollama flag)
```
